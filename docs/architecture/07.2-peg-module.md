## 7.2 PEG Module

PEG owns the workflow and approval lifecycle associated with an AxData object.

PEG is responsible for:

- Workflow applicability and initiation.
- Approval task creation and routing.
- Current approval level and approver(s).
- Approve, Reject, Return, and Recall actions.
- Approver comments and workflow audit history.
- Active PEG workflow state associated with the AxData object.
- Authorization of the initiator/creator and current approver(s) to access or act on the AxData object.
- PEG-related notifications/events ---through the Transactional Outbox/Direct push to queue

  [On final save PEG worflow will be updated in corresponding tables]

During the active AxData lifecycle, PEG workflow state and AxData runtime state are maintained in Redis. The need, timing, and scope of persisting PEG state to `axactivetasks` and `axactivetaskstatus` will be finalized as part of the detailed implementation and recovery design.
