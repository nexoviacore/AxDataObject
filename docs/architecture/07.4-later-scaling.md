## 7.4 Later Independent Scaling

AxData and PEG may later be deployed independently if required for scaling, availability, team ownership, or release cadence.

When separated:

- AxData remains the owner of AxData runtime state and Redis objects.
- PEG remains the owner of PEG workflow state.
- PEG must not directly modify AxData Redis state.
- AxData must not directly modify PEG internal state.
- Cross-service communication must use defined APIs/contracts or events.
- Critical cross-service operations should use idempotent commands and the Transactional Outbox pattern.
- A Saga/process orchestration approach may be introduced later for complex multi-step workflows spanning both services.

The key principle is:

```text
AxData owns AxData state.
PEG owns PEG state.
Cross-module/service changes happen through defined contracts.
```
