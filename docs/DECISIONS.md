## DataObject-state supersession notes

- D37 supersedes D5/D11 only for the active DataObject snapshot transport, SQL recovery, and worker scope; those components are dormant and unwired.
- D38 supersedes the stored-definition binding portions of D8, D28, D33, and D35. Operations load the current StructDef and no `AXD-CONC-003` path remains.
- D39 supersedes D35's v1/v2/v3 compatibility format: active state is discriminator-free, positional, and current-only.
- D40 supersedes owner portions of earlier authorization/storage decisions; persisted `initiatorUserName` plus trusted live identity establishes the initiator relation.
- D41 supersedes DataObject version/CAS portions of D4, D5, D11, D36, and D39. Retained Save returns to `Active` without advancing an object version.
- D42 corrects D39's unspecified typed/sparse encoding: native JSON scalars and sparse array pairs are the required wire contract.
- D43 clarifies D34: successful Init output is a clean baseline, not a set of dirty null-origin fields.
- D44 removes active-state timestamps; D49 supersedes its expiry mechanism because active Redis state now has no TTL.
- D49 supersedes the active-state inactivity-TTL portions of D11 and D44 while durable recovery remains inactive.
- D46 supersedes D42's sparse source/original arrays with source-key-only packed values and optional aligned `oldValues`; D42's native scalar rule remains for non-source-key fields.
- D47 refines D39/D46 field descriptors: compact flags persist only the static read-only and source-key facts needed by Query/Get, while mutation/Save paths still validate them against current StructDef.
