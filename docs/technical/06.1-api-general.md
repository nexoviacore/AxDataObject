### 6.1 General

- Base path: `/api/v1`.
- JSON UTF-8 request/response.
- Authenticated tenant and user come from trusted claims/context, not client-supplied ownership fields.
- Object-changing requests rely on server-owned per-object exclusion. DataObject versions and client concurrency metadata are absent.
- Every response includes a correlation ID.
- HTTP status communicates transport/system outcome; the body includes structured business/validation errors.

The active DataObject operations use explicit POST routes:

- `POST /api/v1/axdata/init`
- `POST /api/v1/axdata/get`
- `POST /api/v1/axdata/set`

Get and Set carry `objectId` in the JSON payload. AxPut Save retains its separate existing contract.

Recommended headers:

```http
Authorization: Bearer <token>
X-Correlation-Id: <client-or-server-generated-id>
```

`If-Match`, `expectedVersion`, and `Idempotency-Key` are not accepted or interpreted by the current DataObject/Save contract. Workflow actions may retain their own expected workflow version; that is separate from the removed object version.
