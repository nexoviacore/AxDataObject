### 6.5 Submit for PEG approval

The architecture separates PEG approval from explicit database persistence when `SaveOnApprove=false`. A distinct submit operation is therefore recommended so API intent is unambiguous:

```http
POST /api/v1/axdata/{objectId}/submit
```

```json
{
  "comments": "Submitted for approval"
}
```

Response:

```json
{
  "status": "pending_approval",
  "objectId": "01J...",
  "workflowInstanceId": "PEG-...",
  "approvalLevel": 1
}
```

This is a future PEG contract. Its expected workflow version and eventual idempotency key belong to workflow consistency, not the removed DataObject version. The domain operations remain distinct: `SubmitForApproval` changes workflow state, while AxPut persists business tables.
