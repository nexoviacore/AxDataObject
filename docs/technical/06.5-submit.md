### 6.5 Submit for PEG approval

The architecture separates PEG approval from explicit database persistence when `SaveOnApprove=false`. A distinct submit operation is therefore recommended so API intent is unambiguous:

```http
POST /api/v1/axdata/{objectId}/submit
If-Match: "13"
Idempotency-Key: 01J-submit-001
```

```json
{
  "comments": "Submitted for approval"
}
```

Response:

```json
{
  "status": "pending_approval",
  "objectId": "01J...",
  "version": 14,
  "workflowInstanceId": "PEG-...",
  "approvalLevel": 1
}
```

If compatibility requires the existing Save API to initiate PEG, the API layer may translate the first Save call into this Submit use case. The domain operations must still remain distinct: `SubmitForApproval` changes workflow state, while `PersistBusinessData` writes transaction tables.
