## 6.6 Save business data

Business Save is owned by AxTstructData:

```http
POST /api/v1/AxPut
If-Match: "14"
Idempotency-Key: 01J-save-001   # required after the idempotency slice
```

```json
{
  "objectid": "01J...",
  "retainDataObject": true,
  "data": [
    {
      "transid": "sales",
      "action": "edit",
      "submitData": {}
    }
  ]
}
```

All calls are ObjectId-aware. When `objectid` is omitted, AxPut generates one. When `retainDataObject` is omitted, it defaults to true. `retainDataObject=false` means use the DataObject for Save and close/destroy it only after successful commit; it never bypasses DataObject processing.

For an existing ObjectId, `data` may be omitted and AxPut saves the current stored object. When `data` is present, submitted values overlay the stored state. Missing or empty `{}` `submitData` performs no overlay but may still write hydrated/default/autogenerated values. A new ObjectId requires a `data` item so TransId/action are known.

Successful response retains the existing AxPut envelope and adds ObjectId state:

```json
{
  "success": true,
  "data": {
    "objectid": "01J...",
    "version": 15,
    "dataObjectRetained": true,
    "data": []
  }
}
```

On failure, return the known current version or omit `version`; never emit `version: null`. Validation/SQL/transaction failure retains the object. Unknown ObjectId returns the supplied ObjectId but omits version.

The Save operation follows the PEG matrix:

| PEG applicability/state | SaveOnApprove | AxPut Save behavior |
|---|---:|---|
| No PEG applicable | Either | Persist immediately |
| PEG not yet initiated | `true` | Submit/initiate PEG; do not persist business data |
| PEG pending | `true` | Reject public Save; final approval invokes trusted AxPut Save |
| PEG approved | `true` | Return the idempotent saved result |
| PEG not yet initiated or pending | `false` | Do not persist; submit/complete PEG first |
| PEG approved | `false` | Persist current DataObject state |
| PEG rejected/recalled | Either | Reject unless a configured reopen/reversal rule allows it |

Bulk semantics are a later explicit contract; one ObjectId represents one primary DataObject in the initial implementation.
