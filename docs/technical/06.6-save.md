### 6.6 Save business data

```http
POST /api/v1/axdata/{objectId}/save
If-Match: "14"
Idempotency-Key: 01J-save-001
```

```json
{
  "responseFields": ["recordid", "orderno"],
  "callerId": "bulk-import-884",
  "sequence": 7
}
```

The Save operation follows this state matrix:

| PEG applicability/state | SaveOnApprove | Public Save behavior |
|---|---:|---|
| No PEG applicable | Either | Persist immediately |
| PEG not yet initiated | `true` | Submit/initiate PEG; do not persist business data |
| PEG pending | `true` | Reject public Save; final approval invokes trusted internal Save |
| PEG approved | `true` | Already saved by final approval; return the idempotent saved result |
| PEG not yet initiated or pending | `false` | Do not persist; submit/complete PEG first |
| PEG approved | `false` | Explicitly persist current Redis AxData state |
| PEG rejected/recalled | Either | Reject unless a configured reopen/reversal rule allows it |

Successful persistence response:

```json
{
  "status": "saved",
  "objectId": "01J...",
  "version": 15,
  "recordId": 100502,
  "fields": {
    "orderno": "SO-100502"
  },
  "workflow": {
    "status": "approved"
  },
  "artifacts": []
}
```

For `SaveOnApprove=true`, final approval calls the same business-save use case through a trusted internal application contract. For `SaveOnApprove=false`, final approval returns `approved_awaiting_save`; the client must then call this explicit Save API.
