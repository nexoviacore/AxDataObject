### 6.8 PEG task APIs

```http
GET  /api/v1/peg/tasks
GET  /api/v1/peg/tasks/{taskId}
POST /api/v1/peg/tasks/{taskId}/approve
POST /api/v1/peg/tasks/{taskId}/reject
POST /api/v1/peg/tasks/{taskId}/return
POST /api/v1/peg/instances/{workflowInstanceId}/recall
```

Approve example:

```json
{
  "comments": "Approved",
  "expectedWorkflowVersion": 3
}
```

Return example:

```json
{
  "comments": "Correct the quantity.",
  "returnTo": "user1",
  "expectedWorkflowVersion": 3
}
```

Every action requires an idempotency key. The workflow task identifies ObjectId; ObjectId alone is not sufficient to select an approval task when multiple tasks/approvers exist.

On final approval:

- `SaveOnApprove=true`: PEG invokes the trusted internal AxData Save; the response is `approved` only after that Save succeeds.
- `SaveOnApprove=false`: PEG completes without a business-data write and returns `approved_awaiting_save`. The authorized client subsequently calls the explicit AxData Save API.
